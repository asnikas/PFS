# PFS roadmap

Черновик от 2026-10-16 (предложен вместе с Claude). Автор проекта правит под себя: порядок, обоснования, что вычеркнуть, что добавить.

Единицы: часы. Ритм: 3,5 ч в день. Жёсткая граница проекта: **20 ноября 2026** (потом стажировка, отчёт 4 декабря, затем железный проект).

Статус: `[ ]` не начато, `[~]` в работе, `[x]` готово. **M** — обязательно, **D** — желательно.

## Принципы

- Перед крупным блоком (аллокатор, ключи) сначала пишу короткую заметку с форматом и инвариантами, потом код.
- Аллокатор, SHA-256/PBKDF2, ChaCha20, разбор путей пишу сам. Инфраструктуру (запускалка тестов, механический разнос на `.h`/`.cpp`) может делать помощник, фиксирую это в README.
- Один коммит = одна законченная мысль. Каждый коммит собирается и проходит сценарии.
- Решения, которые отличаются от исходного ТЗ, записываю в README с обоснованием (например, вместо потока TEMP внутри образа: буфер в памяти с обнулением).

## Итого

- Обязательное: около 95 ч.
- Желательное: около 32 ч.
- Порядок отсечения, если не хватает времени: бенчмарки, диаграмма v2, `tree`, `fsck`, Tab-автодополнение, отзыв доступа, `import`/`export`, GitHub Actions, чтение кусками.
- Не отсекаем: сценарии, аллокатор, пароль с ChaCha20 и MAC, `cd ..` с путями, ошибки, README.

## Известные ограничения (для README)

- Образ и файлы до ~2 ГБ (адреса и размеры потоков `int`).
- Файл читается и пишется целиком через память.
- `mkfs` стирает образ без подтверждения (только ADMIN).
- Ключи пользователей в открытом виде до пункта 22.
- Только ADMIN меняет права каталогов (осознанное решение).
